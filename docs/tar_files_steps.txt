tar_files/ - minimal offline transfer bundle (same as offlin_bundle, trimmed further)
======================================================================================
output.json.gz here is a 30,000-record sample (2.9MB), not the full 11.3GB corpus.

Copy this whole "tar_files" folder to the VM, then:

cd tar_files
chmod +x ingestion_pipeline/*.sh chatbot_pipeline/*.sh   # safety net, in case transfer didn't preserve +x

cd ingestion_pipeline
docker load -i ingestion_image.tar && docker load -i neo4j_image.tar
./offline_ingest_sample.sh          # first 5000 records + embeddings, ~40 min on CPU
# or: LIMIT=20000 ./offline_ingest_sample.sh   # any value up to 30000 (that's all this bundle carries)

cd ../chatbot_pipeline
docker load -i chatbot_backend_image.tar && docker load -i chatbot_frontend_image.tar
./offline_start_chatbot.sh          # needs native Ollama + qwen3:14b already running on the VM

# Browser: http://<vm-ip>:3000   Neo4j Browser: http://<vm-ip>:7474 (neo4j/sandboxpassword)

Notes
-----
- LIMIT can be at most 30000 (that's the whole sample file included here).
- offline_start_chatbot.sh needs native Ollama + qwen3:14b already running on
  the VM - not included here, not part of this project.
- frontend/ only has Dockerfile+nginx.conf (no source) - fine, since
  chatbot-frontend:latest is already a built image; nothing rebuilds it.
